`mintctl deploy staging` builds the current `HEAD` of `mint-shop`, pushes it, rolls it out to `gke-mint-staging` and posts to `#deploys-staging`. The code only shows `deploy(env_name)` in `mintctl/deploy.py`. No file here parses the command line, so the call `deploy("staging")` is assumed.

**Timeline**

1. **Config.** `deploy` opens `mint.toml` in the current directory. Ines Albrecht must run it from the `mint-shop` root. It reads `env.staging`: cluster `gke-mint-staging`, namespace `shop`, channel `#deploys-staging`.
2. **Version.** `git rev-parse --short HEAD` gives the short sha. Uncommitted changes are not part of the sha, but `docker build` still includes them.
3. **Tag.** The image tag is `registry.mint.internal/mint-shop:<sha>`. `HOST` comes from `mintctl/registry.py`.
4. **Build and push.** `docker build -t <tag> .` runs, then `docker push <tag>`. Both use `check=True`, so a failure stops the deploy with an exception.
5. **Release.** `kubectl --context gke-mint-staging -n shop set image deployment/mint-shop web=<tag>` points the `web` container at the new image.
6. **Wait.** `kubectl rollout status deployment/mint-shop --timeout=300s` blocks for up to 300 seconds. A timeout or failed rollout stops the deploy before Slack.
7. **Notify.** `slack.post` sends `mint-shop <sha> is live on staging` to `#deploys-staging`. It uses the webhook in `MINT_SLACK_WEBHOOK`, with a 10 second timeout. A missing variable raises `KeyError` after the rollout has already succeeded.
