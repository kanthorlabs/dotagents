`mintctl deploy staging` builds the current commit of `mint-shop` as an image, pushes it, rolls it out to the staging cluster and posts to Slack. All of this runs from Ines Albrecht's machine, in the directory where they run the command.

**Timeline**

1. **Entry.** `mintctl` calls `deploy("staging")` in `mintctl/deploy.py:7`. The code that parses the command line is not in this directory, so I could not check this step.
2. **Config.** `deploy` opens `mint.toml` in the current directory. It reads `env.staging`: cluster `gke-mint-staging`, namespace `shop`, channel `#deploys-staging`. An unknown env name raises `KeyError`.
3. **Version.** `git rev-parse --short HEAD` gives the short commit hash. Call it `sha`. Uncommitted changes are not part of `sha`, but `docker build` still includes them.
4. **Build.** The tag is `registry.mint.internal/mint-shop:<sha>`. `docker build -t <tag> .` runs in the current directory.
5. **Push.** `docker push <tag>` sends the image to `registry.mint.internal`. It uses the Docker login of Ines Albrecht.
6. **Release.** `kubectl --context gke-mint-staging -n shop set image deployment/mint-shop web=<tag>` points the `web` container at the new image.
7. **Wait.** `kubectl ... rollout status deployment/mint-shop --timeout=300s` blocks until the rollout finishes or 300 seconds pass. A failure at any of steps 4 to 7 raises an error, because of `check=True`. The Slack post is then skipped.
8. **Notify.** `slack.post` sends `mint-shop <sha> is live on staging` to `#deploys-staging`. It uses the webhook in the `MINT_SLACK_WEBHOOK` environment variable. The `channel` field in the payload may be ignored, because many Slack webhooks are bound to one channel.
