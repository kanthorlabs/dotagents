`handle` in `quillpay/webhooks.py` credits and debits the ledger before it checks the signature, so anyone can mint money. Aelita recommends blocking the merge on B1 to B4. B1 is the first item to settle.

**Timeline without the fix**

1. An attacker posts `charge.succeeded` for account 77 with `amount_cents` 1000000 to the webhook URL, with the header `Quill-Signature: t=1`.
2. `handle` runs `json.loads` on the body. It accepts the body without any check.
3. `handle` logs the full payload at line 20.
4. `ledger.credit` runs for account 77 at line 23. The balance rises by 10000 EUR.
5. `verify` runs at line 27. The timestamp is stale, so it returns False.
6. `handle` returns 400. The credit is already committed, so the attacker repeats the call. An empty header makes `verify` raise `ValueError` instead, and the credit stays.

**Timeline with the fix**, diverges at step 4.

4. `handle` calls `verify` before it touches the body. The stale timestamp returns False.
5. `handle` returns 400. No ledger call happens.

**What changes**

- `quillpay/webhooks.py` `handle`: old behaviour runs `verify` after the ledger calls. New behaviour runs `verify` first and returns 400 before `json.loads` and any ledger call.
- `quillpay/webhooks.py` `verify`: old behaviour uses `expected == parts.get("v1")`. New behaviour uses `hmac.compare_digest`. It also returns False on a malformed header instead of raising.
- `quillpay/settings.py`: old line `os.environ.get("QUILL_WEBHOOK_SECRET", "dev-secret")`. New line `os.environ["QUILL_WEBHOOK_SECRET"]`.
- `quillpay/webhooks.py` `_unused_helper`: delete.

**Findings**

- B1 - status:OPEN - action:YES - Ledger mutated before signature check - `handle` credits and debits at lines 22 to 25, then verifies at line 27. - fix:move the `verify` call to the top of `handle` and return 400 on failure. - why:an unsigned request moves money today.
- B2 - status:OPEN - action:YES - Replay and redelivery double-apply - Nothing records the event id. A captured signed request is valid for 300 seconds, and provider retries repeat events. - fix:store the event id with a unique constraint and skip a known id, in the same transaction as the ledger call. - why:a duplicate `charge.succeeded` credits the account twice.
- B3 - status:OPEN - action:YES - Default secret `dev-secret` - `settings.py` falls back to a public string when the env var is missing. - fix:read `os.environ["QUILL_WEBHOOK_SECRET"]` so the app fails at start. - why:a misconfigured deploy lets anyone forge valid signatures.
- B4 - status:OPEN - action:YES - Non-constant-time compare - `verify` compares the digests with `==` at line 42. - fix:use `hmac.compare_digest`. - why:`==` leaks timing information about the expected signature.
- S1 - status:OPEN - action:YES - Malformed input raises 500 - A bad header, a non-integer `t`, invalid JSON or a missing `data` key raises an exception. - fix:catch `ValueError` and `KeyError` and return 400. - why:providers retry on 5xx, which floods the endpoint.
- S2 - status:OPEN - action:YES - Full payload logged - Line 20 logs the raw body at info level. - fix:log the event id and type only. - why:the body holds account data that should stay out of logs.
- S3 - status:OPEN - action:YES - Dead code - `_unused_helper` has no caller. - fix:delete it. - why:it adds noise to a payment module.
- S4 - status:OPEN - action:NO - Unknown event types return 200 silently - Other types fall through without a log line. - fix:log the type at debug level. - why:it helps diagnose missing handlers, and 200 is correct for ignored events.

**Recommendation.** Aelita recommends the verify-first ordering from B1. It removes the root cause, costs one reordered block, and leaves the HMAC logic unchanged. It can break a test that posts unsigned bodies, and those tests need a signing helper. The alternative is a decorator that wraps `handle` with `verify`. It is reusable across handlers, but it adds a layer for one endpoint. I ranked it lower for that reason.
