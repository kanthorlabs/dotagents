`handle` in `quillpay/webhooks.py` changes the ledger before it checks the signature, so anyone can forge a credit. Aelita recommends blocking PR 311 until B1 to B3 are fixed. B1 and B2 are small edits.

**Existing behaviour**

1. `handle` parses the body and logs it (`pr-311.diff:19-20`).
2. `handle` calls `ledger.credit` or `ledger.debit` by event type (`pr-311.diff:22-25`).
3. `handle` calls `verify` and returns 400 or 200 (`pr-311.diff:27-29`).

**Timeline without the fix**

1. An attacker posts `{"type":"charge.succeeded","data":{"account_id":"acc_9","amount_cents":500000}}` with no `Quill-Signature` header.
2. `handle` parses the body and logs it.
3. `handle` calls `ledger.credit("acc_9", 500000)`. The ledger now holds the credit.
4. `verify` gets an empty header. `dict()` raises `ValueError` and the request ends in a 500. With a bad but well-formed header, it returns 400.
5. The error response does not undo the credit.
6. The attacker repeats the request. `acc_9` is credited with money that never moved.

**Timeline with the fix**, diverges at step 2.

2. `handle` calls `verify` first. It finds no valid signature and returns 400.
3. `ledger.credit` is never called. The forged event changes nothing.

**What changes**

- `quillpay/webhooks.py` old behaviour: `handle` mutates the ledger, then verifies. New behaviour: `handle` verifies first, then parses and mutates.
- `quillpay/webhooks.py` old behaviour: `verify` raises on a malformed header. New behaviour: it returns `False`.
- `quillpay/settings.py` old behaviour: `os.environ.get("QUILL_WEBHOOK_SECRET", "dev-secret")`. New behaviour: `os.environ["QUILL_WEBHOOK_SECRET"]`, which matches `DATABASE_URL` on the line above.

**Recommendation.** Aelita recommends moving `verify` to the top of `handle` and removing the secret default. Both are small edits that remove the cause. The only break is that deployments without `QUILL_WEBHOOK_SECRET` fail at import. That is the intended outcome.

**Findings**

- `B1 - status:OPEN - action:YES - Ledger changes before signature check - handle calls ledger.credit and ledger.debit before verify at pr-311.diff:22-29, so unsigned requests move money - fix:call verify first and return 400 before any parsing - why:any internet client can forge credits`
- `B2 - status:OPEN - action:YES - Default signing secret - settings.py:52 falls back to "dev-secret" when the env var is missing - fix:use os.environ["QUILL_WEBHOOK_SECRET"] - why:a missing variable in production lets anyone compute a valid signature`
- `B3 - status:OPEN - action:YES - No replay or retry protection - handle never records event ids, so a provider retry or a replay inside the 300 second window credits twice - fix:store event["id"] with a unique constraint and skip duplicates, in the same transaction as the ledger write - why:payment providers retry by design`
- `S1 - status:OPEN - action:YES - Malformed header raises - verify at pr-311.diff:33-34 fails on an empty header or a non-numeric t - fix:wrap the parsing in try/except (ValueError) and return False - why:a bad request should give 400, not 500`
- `S2 - status:OPEN - action:YES - Non-constant-time compare - verify uses == at pr-311.diff:42 - fix:use hmac.compare_digest - why:it removes a timing side channel`
- `S3 - status:OPEN - action:YES - Raw payload logged - log.info at pr-311.diff:20 logs the full body before verification - fix:log event id and type after verification - why:it leaks account data and lets unsigned callers write to logs`
- `S4 - status:OPEN - action:YES - Unvalidated event fields - json.loads, event["type"] and event["data"][...] raise on bad input, and amount_cents and currency are not checked against LEDGER_CURRENCY - fix:return 400 on a bad shape and reject non-positive amounts - why:bad input should not cause 500s or negative credits`
- `S5 - status:OPEN - action:YES - Dead code and no tests - _unused_helper at pr-311.diff:45-46 does nothing, and the diff adds no tests - fix:delete the helper and add tests for forged, stale, replayed and valid events - why:a payment path needs regression cover`
