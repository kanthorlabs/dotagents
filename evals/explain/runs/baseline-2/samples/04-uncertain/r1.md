`report-builder` returned an empty October report for `northwind` because migration 0042 archived every paid invoice, and `northwind` had `hide_archived` on in the cached flags. Aelita recommends fixing the migration's missing 90-day filter and restoring the wrongly archived rows.

**Timeline without the fix**

1. Migration 0042 runs on 25 October at 22:10 UTC. The README says it archives paid invoices older than 90 days. `migrations/0042_archive_paid_invoices.sql:2-4` has no age condition, so it archives every paid invoice.
2. All 188 October invoices of `northwind` were paid, and all 188 are now `archived`. `invoice-counts-2026-10-26.txt` shows 0 paid and 188 archived.
3. `report-builder` starts on 26 October at 02:00 UTC. `flagd` is unreachable, so `ledgerly.flags` serves cached flags that are 3 days old (log line 2).
4. `build_monthly_report` calls `flags.is_on("hide_archived", tenant="northwind")`. The result must be on, though I cannot see the cache. `jobs/report_builder.py:10-11` then adds `AND status <> 'archived'`.
5. The query for `northwind` matches 0 of its 188 October invoices. The log records `invoices=0 report=ok`, so the job reports success.

**Evidence for step 4.** `acme` has 301 archived invoices out of 412 and `globex` has 64 out of 97. Their reports still show 412 and 97 invoices, so `hide_archived` was off for them. Only `northwind` shows a count that matches the filter being on.

**Unverified.** The cache content and the live `flagd` value for `northwind` are not in the repository. The cache file or the `flagd` audit log would settle them. Neither changes the fix, because the migration is the root cause.

**Timeline with the fix**, diverges at step 1.

1. Migration 0042 adds `AND issued_at < now() - interval '90 days'`. October invoices stay `paid`.
2. `northwind` keeps 188 paid invoices.
3. The cached flags are still stale.
4. `hide_archived` is on, but the filter only excludes `archived` rows.
5. The query returns 188 invoices. The October report is complete.

**What changes**

- `migrations/0042_archive_paid_invoices.sql`: add the 90-day condition on `issued_at`.
- New repair migration: set `status = 'paid'` for rows that 0042 archived with `issued_at` newer than 90 days before 25 October.
- `jobs/report_builder.py`: no change. The filter works as written.

**Recommendation.** Aelita recommends the migration fix plus the repair. It removes the root cause, which is the overbroad `UPDATE`. The cost is a repair query that cannot tell 0042 archives from earlier archives. Any invoice archived on purpose before 25 October and issued in the last 90 days would be wrongly restored.

**Alternative: stop `hide_archived` from hiding invoices in reports.** Remove the flag from `build_monthly_report`. It is the fastest fix and needs no data repair. It becomes the primary if the product rules out hiding archived invoices from monthly reports. It leaves 0042's bad data in place.
