The October report for `northwind` was empty because migration 0042 archived all 188 of its paid invoices, and `report-builder` hid them. The migration ignores its own 90-day rule. The one step I can't verify is that the cached `hide_archived` flag was on for `northwind`.

**Existing behaviour**

1. `migrations/README.md` says 0042 archives paid invoices older than 90 days.
2. `migrations/0042_archive_paid_invoices.sql:2-4` runs `UPDATE invoices SET status = 'archived' WHERE status = 'paid'`. It has no age condition.
3. `jobs/report_builder.py:5-11` reads `hide_archived` per tenant. When the flag is on, it adds `AND status <> 'archived'`.

**Timeline without the fix**

1. About 23 Oct, `report-builder` last had fresh flags. The log says the cache was 3 days old on 26 Oct. This date is inferred.
2. On 25 Oct at 22:10 UTC, 0042 sets every `paid` invoice to `archived`. Priya Raman's counts show `northwind` with 188 issued in October, 0 paid and 188 archived.
3. On 26 Oct at 02:00:01, `report-builder` starts. It logs `flagd unreachable, using cached flags`.
4. **Unverified:** `flags.is_on("hide_archived", tenant="northwind")` returns true from the cache. Priya Raman's counts support this. `acme` shows 412 in the report against 301 archived, and `globex` shows 97 against 64 archived. So the flag was off for those two, and only `northwind` fits "on".
5. The `northwind` query excludes all 188 archived rows. The log shows `invoices=0 report=ok`.
6. The job reports success and `northwind` gets an empty October report.

An audit log from `flagd`, or the cached flag file, would settle step 4. I skip the fixed timeline until then.

**Recommendation.** Aelita recommends fixing the data first, because the migration is the root cause. A corrective migration would restore to `paid` every invoice that 0042 archived and that was issued within 90 days of 25 Oct. That brings back the October rows. The cost is that I can't tell pre-existing `archived` rows from 0042's rows, so some could be restored wrongly. Checking `issued_at` and any audit column would narrow that.

**Alternative: turn `hide_archived` off for `northwind`.** This needs no data change. It would also show old archived invoices, and it needs `flagd` access. It becomes the primary if the archived status turns out to be correct.
