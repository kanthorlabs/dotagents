`legacy_sku` is not unused. `v_partner_feed` reads it, and the nightly `partner_feed_export` sends it to Oakline Supply. Aelita recommends keeping the column for now. Drop it only after Oakline Supply stops keying on Brightstock codes.

**Why the `src/` grep missed it.** The readers sit outside `src/`: `db/views.sql:4`, `jobs/partner_feed_export.py:7` and `importers/brightstock_import.py:4`.

**Timeline without the fix**

1. A migration runs `ALTER TABLE products DROP COLUMN legacy_sku`.
2. Postgres rejects it, because `v_partner_feed` depends on the column.
3. A developer clears the error. They either use `CASCADE`, which drops the view, or they edit the view to `p.sku AS partner_ref`.
4. The nightly `partner_feed_export` runs. With `CASCADE` it fails on the missing view. With the edited view it sends the new `sku` as `partner_ref`.
5. Oakline Supply receives `/inbound/cartwheel.csv` with codes it does not know.
6. Oakline Supply cannot match the 6,140 migrated products. The partner catalog breaks.

**Timeline with the fix**, diverges at step 1.

1. Oakline Supply confirms it keys on the new `sku` and loads the new codes.
2. A developer edits `v_partner_feed` so that `partner_ref` is `p.sku`.
3. `partner_feed_export` sends the new codes. Oakline Supply matches every product.
4. The migration drops `legacy_sku`. Nothing depends on it, so it succeeds.

**What changes**

- `db/views.sql`: old `COALESCE(p.legacy_sku, p.sku) AS partner_ref`. New `p.sku AS partner_ref`. This lands before the drop.
- `db/schema.sql`: delete the `legacy_sku text,` line, and add the `DROP COLUMN` migration after the view change.
- `importers/brightstock_import.py`: the INSERT names `legacy_sku`, so it would fail after the drop. The doc says the import ran once on 12 March 2024. Delete the importer, or remove the column from its INSERT.
- `docs/history/2024-brightstock-migration.md`: add a line saying the column was dropped and why.

**Recommendation.** Aelita recommends keeping the column until Oakline Supply re-keys. The column costs one nullable text field. Dropping it early breaks the nightly feed, and the Brightstock codes cannot be rebuilt once the data is gone.

**Alternative: drop now and send `sku` anyway.** This removes the column today. It beats the recommendation if Oakline Supply has already re-keyed. It costs a broken feed if that is false. It becomes the primary if you confirm the re-key.
