The retry limit is the next open item. `BOUNCE_RETRY_LIMIT = 12` exceeds the `smtp-mx-2` bounce limit, so one bad mailbox blocks every invoice for 24 hours. Aelita recommends failing hard bounces at once and capping soft retries at 4. The cutover date for `smtp-old-1` follows after your answer.

**Timeline without the fix**

1. Larkspur sends INV-2207 to a mistyped mailbox for Oskar Brandt. `smtp-mx-2` reports a hard bounce.
2. `handle_bounce` cannot tell hard from soft. It waits 60 seconds and resends.
3. The mailbox still does not exist. Bounces 2 to 5 arrive, one per minute.
4. The sixth bounce arrives about 5 minutes in. `smtp-mx-2` blocks `invoices@mail.larkspur.io` for 24 hours.
5. `handle_bounce` keeps retrying until attempt 12, then calls `mark_failed`.
6. Larkspur cannot send any invoice to any customer for 24 hours. One bad mailbox stops all billing.

**Timeline with the fix**, diverges at step 2.

2. `handle_bounce` sees a hard bounce. It calls `mark_failed` at once and sends nothing more.
3. `smtp-mx-2` counts one bounce for that mailbox. The sender stays unblocked and other invoices go out.

**What changes**

- `mailer/bounces.py` `handle_bounce`: add a check at the top. A hard bounce calls `message.mark_failed()` and returns. Soft bounces keep the current retry path.
- `mailer/config.py` `BOUNCE_RETRY_LIMIT`: old value 12, new value 4. This keeps one recipient at 5 bounces or fewer per hour, whether `attempt` starts at 0 or 1.

**Recommendation.** Aelita recommends both edits. The hard-bounce check removes the cause, because retrying a missing mailbox never works. The lower limit protects soft bounces from the 5-per-hour rule. The cost is that `handle_bounce` needs the bounce type. No file in this repo calls `handle_bounce`, so I cannot see where that type would come from.

**Alternative: lower the limit only.** Set `BOUNCE_RETRY_LIMIT = 4` and add no classification. It needs no bounce type and is a one-line change. A missing mailbox still uses 4 or 5 bounces before it fails. It becomes the primary when the caller cannot pass the bounce type to `handle_bounce`.
