`plugin_env` copies the whole runner environment and removes only three named secrets. Any secret added later reaches every plugin. Aelita recommends an allowlist in `runner/spawn.py` instead of your two-name denylist, because the denylist still leaves `BILLING_WEBHOOK_SECRET` exposed.

**Timeline without the fix**

1. Ops adds `STRIPE_API_KEY` to `deploy/runner.env` on 2 October. The file already holds `SENTRY_DSN` and `BILLING_WEBHOOK_SECRET`.
2. `run_plugin` calls `plugin_env`. It copies `os.environ` and pops only `AWS_SECRET_ACCESS_KEY`, `DATABASE_URL` and `GITHUB_TOKEN`.
3. The `feed-fetch` plugin starts with `STRIPE_API_KEY`, `SENTRY_DSN` and `BILLING_WEBHOOK_SECRET` in its environment.
4. A customer sends a `feed-fetch` request with `debug` set. `plugins/feed-fetch/main.py:14` prints `dict(os.environ)` to stderr.
5. The customer pastes that stderr into a public support ticket on 24 October. Selin Aydin reports it as INC-57.
6. The key is rotated on 24 October. Your two-name fix would stop this repeat, but `BILLING_WEBHOOK_SECRET` would still leak the same way.

**Timeline with the fix**, diverges at step 2.

2. `plugin_env` builds a new dict. It keeps only `PATH`, `HOME`, `LANG`, `HTTPS_PROXY` and every `TINKERBOX_*` variable.
3. The `feed-fetch` plugin starts with no secrets in its environment.
4. The `debug` request still prints the environment. The output holds only the allowed variables.
5. The customer has nothing sensitive to paste.
6. A secret added to `deploy/runner.env` next month stays hidden by default.

**What changes**

- `runner/spawn.py`: delete `DENYLIST` and the pop loop. Add `ALLOWED = {"PATH", "HOME", "LANG", "HTTPS_PROXY"}`. `plugin_env` returns `{k: v for k, v in os.environ.items() if k in ALLOWED or k.startswith("TINKERBOX_")}`. The `TINKERBOX_PLUGIN_DIR` assignment stays.
- `plugins/feed-fetch/main.py`: no change is required. Line 14 is harmless once the environment is clean.

**Recommendation.** Aelita recommends the allowlist. It removes the root cause, which is inheriting everything by default. The contract in `docs/plugin-contract.md` says plugins read `TINKERBOX_*`. The existing plugins need only `HOME` (`pdf-stamp`), `HTTPS_PROXY` (`feed-fetch`) and `PATH` (`qpdf`). The cost is that a plugin needing another variable fails until someone adds it to `ALLOWED`. I checked the three plugins in the repo. I have not checked any plugin outside it.

**Alternative: extend the denylist.** Add `STRIPE_API_KEY`, `SENTRY_DSN` and `BILLING_WEBHOOK_SECRET` to `DENYLIST`. It is a one-line change and cannot break a plugin. It becomes the primary if third-party plugins in `/srv/tinkerbox/plugins` are known to rely on unlisted variables. It leaves this class of leak open.

**Alternative: remove the debug dump.** Delete `plugins/feed-fetch/main.py:14`. It closes this one path. Other plugins can still print their environment.
