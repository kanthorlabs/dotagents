`purge-worker` deleted the in-progress uploads because `TenantConfig.validate` accepts `retention_days: 0`, which `docs/retention.md` does not support. Aelita recommends that `validate` reject 0, so the cutoff can never fall inside the 6-hour window of a multipart upload.

**Timeline without the fix**

1. `tenants/acme-labs.yaml` sets `retention_days: 0`.
2. `validate` in `config/schema.py` checks `retention_days < 0`. The value 0 passes.
3. A user of `acme-labs` starts a multipart upload at 10:00. It can run for up to 6 hours.
4. `purge-worker` runs at 10:15. `purge_tenant` computes `cutoff = now - timedelta(days=0)`, which is 10:15.
5. `purge_tenant` compares `upload.created_at < cutoff`. 10:00 is before 10:15, so the test is true.
6. `store.delete` removes the upload while it is still in progress.

**Timeline with the fix**, diverges at step 2.

2. `validate` checks `retention_days < 1`. The value 0 raises `ValueError`, and the `acme-labs` config does not load.
3. The `acme-labs` owner picks a value of 1 or more. For example, `retention_days: 1` is accepted.
4. A user starts an upload at 10:00. At 10:15 the cutoff is `now - 1 day`, which is yesterday 10:15.
5. `upload.created_at < cutoff` is false.
6. The upload survives and completes. Any value of 1 day or more exceeds the 6-hour limit.

**What changes**

- `config/schema.py` old behaviour: `validate` raises only when `retention_days < 0`. New behaviour: it raises when `retention_days < 1`. The message becomes `retention_days must be >= 1`.
- `tenants/acme-labs.yaml` old value: `retention_days: 0`. New value: a tenant decision, at least 1.

**Recommendation.** Aelita recommends forbidding 0, because the root cause is that the schema allows a value the docs forbid. This adds no new mechanism. It costs one changed line. Any tenant file that sets 0 now fails to load, so I must check the other tenants. Only `acme-labs.yaml` exists in this repo.

**Alternative: skip in-progress uploads in `purge_tenant`.** `purge_tenant` would skip any upload that has not completed. It protects uploads even if the config is wrong. It costs a status field on `upload`. `store` is not in this repo, so I cannot confirm that field exists. It becomes the primary if tenants need a retention shorter than 6 hours.

**Question.** Do you approve rejecting `retention_days: 0` in `validate`? The value for `acme-labs` follows after your answer. Tenants that want no retention already delete uploads through the API.
