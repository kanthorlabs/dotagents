Halvorsen Marine's uploads fail because two limits of 10 MB each reject any file over 10 MB. Aelita recommends raising both limits to 200 MB for `/api/files` only. That works without a frontend release.

**Timeline without the fix**

1. Eirik Dahl uploads a 94 MB drawing. The web client sends a plain form POST to `/api/files`.
2. `nginx` reads the header and sees a body of 94371840 bytes. `client_max_body_size 10m` in `deploy/nginx/pinewood.conf:8` applies.
3. `nginx` returns 413 and logs `client intended to send too large body`. The log shows this at 09:14:02 and again at 09:31:47 for 160 MB.
4. The request never reaches `pinewood-app`.
5. A second limit sits behind the first. `MAX_CONTENT_LENGTH = 10 * 1024 * 1024` in `app/settings.py:3` is loaded by `create_app`. Flask would also return 413.
6. Fixing only `nginx` moves the 413 to Flask. Every drawing from 60 to 180 MB fails.

**Timeline with the fix**, diverges at step 2.

2. `nginx` accepts the body because `/api/files` allows 200m. It buffers the body to `/var/cache/nginx/client_temp`.
3. The upload from the 20 Mbit/s uplink takes about 72 seconds for 180 MB. `nginx` absorbs this time. The gunicorn `timeout = 30` does not apply.
4. `nginx` forwards the full body to `pinewood-app` at network speed. Flask accepts it under the new 200 MB cap.
5. `storage.put` sends the file to `pinewood-files` at about 60 MB/s. A 180 MB file takes about 3 seconds, so the worker stays under 30 seconds.
6. `upload_file` returns 201 with the key. The drawing is stored.

**What changes**

- `deploy/nginx/pinewood.conf`: add `location = /api/files` with `client_max_body_size 200m;` and the same `proxy_pass` and headers as `/api/`. Other `/api/` routes keep 10m.
- `app/settings.py`: old `MAX_CONTENT_LENGTH` is 10 MiB. New value is 200 MiB.
- `docs/ops.md`: add one line stating the 200 MB limit on `/api/files`.

**Recommendation.** Aelita recommends the two limit changes. Load is small. 25 drawings per day at up to 180 MB is at most 4.5 GB per day through a 20 GB buffer volume. Each upload holds a sync worker for about 3 seconds, so 4 workers are enough. The cost is that Flask's cap is global. `nginx` still guards the other routes at 10m. Because the 200 MB cap covers every account, any customer can now send 200 MB files to `/api/files`. Nothing in the repo suggests that is a problem.

**Alternative: direct upload with `presign_post`.** The browser uploads straight to `pinewood-files`. This removes the body from `nginx` and the workers. It needs a new endpoint and a web client change. The frontend team is away until 9 November, so it misses Friday 30 October. It becomes the primary if uploads grow to many users or files over 200 MB.
