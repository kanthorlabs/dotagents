The stale price comes from the in-process `price_cache` in each of the 6 `shop-api` pods, not from the CDN. Lowering the CDN TTL would change nothing, because `cdn/rules.yaml:10-11` already sets `cache: false` for `/api/*`. Aelita recommends that each pod evicts its own cache entry when `price.changed` arrives.

**Existing behaviour**

1. `pricing/service.py:5` gives every pod its own `TTLCache` with `ttl=3600`.
2. `get_price` returns the cached value and reads `db` only on a miss.
3. `update_price` in `admin/prices.py:14` calls `price_cache.pop(sku)`. That clears only the pod that served the admin request.
4. `update_price` then publishes `price.changed`. Only `search/indexer.py` subscribes. No pod uses it to clear `price_cache`.

**Timeline without the fix**

1. At 10:02 Tove Lindqvist changes KET-2210 from 39.90 to 34.90. The load balancer sends the request to pod A.
2. Pod A writes `db` and pops KET-2210 from its own `price_cache`.
3. Pods B to F still hold 39.90 in `price_cache`, each from its own earlier read.
4. A product page calls `/api/prices?sku=KET-2210`. The CDN skips `/api/*`, so the load balancer picks any pod.
5. Pod A returns 34.90. Pods B to F return 39.90. Tove sees both values on reloads, as SM-140 reports.
6. Each stale pod keeps 39.90 until its entry expires. The last report came at 10:57, which fits the 3600-second ceiling. Customers pay the old price at checkout.

**Timeline with the fix**, diverges at step 3.

3. Pod A publishes `price.changed`. Every pod runs a subscriber that pops the SKU from its own `price_cache`.
4. The next `/api/prices` call on any pod misses the cache and reads 34.90 from `db`.
5. Every pod returns 34.90 after the event, within about a second.
6. Tove and customers see one price.

**What changes**

- `pricing/service.py`: add `on_price_changed(payload)`, which runs `price_cache.pop(payload["sku"], None)`. Add `start_invalidation()`, which calls `subscribe("price.changed", on_price_changed)`.
- `shop/app.py`: call `start_invalidation()` at startup. This file is not in the repository, so I did not read it. The call goes wherever the app wires `search/indexer.py`.
- `cdn/rules.yaml`: no change. Do not lower any TTL.

**Recommendation.** Aelita recommends event-driven eviction, because `price.changed` already exists and the pods only need to listen. It costs one Redis subscription per pod. Redis pub/sub does not replay events, so a pod that misses one message keeps the old price until its TTL ends. Lowering `ttl` in `pricing/service.py:5` to 300 limits that gap.

**Alternative: lower the pod `ttl` from 3600 to 60.** This is a one-line change in `pricing/service.py`. It needs no subscriber. It still shows old prices for up to 60 seconds, and it raises `db` reads. It becomes the primary if the team will not run a subscriber in every pod.

**Alternative: drop `price_cache` and read `db` every time.** This removes the cause and the staleness. It costs one `db` read per price request. It becomes the primary if `db.fetch_price` is cheap and traffic is low.
