- **Cache key today: correct.** `cache_key` in `edge/cache.py:5` returns `request.path` plus `request.query_string`. It has no format part.
- **Breakage cause: correct.** `docs/browser-support.md` says Safari 13 decodes neither WebP nor AVIF. It gets the cached WebP bytes and shows a broken image.
- **Key with the fix: wrong.** The key does not get the whole `Accept` header. It gets only the negotiated format, which is `avif`, `webp` or `orig`.

The case is not "append the raw `Accept` header". `negotiate` in `edge/negotiate.py` already reduces that header to one of three values. `edge/handler.py:10` calls it on every request.

**Why the raw header is wrong.** `logs/accept-stats-2026-10.txt` counts 1,912 distinct `Accept` values in October. Each value would create its own cache entry for the same image. The hit rate would collapse. The three-value key makes at most three entries per URL.

**Timeline with the fix**, diverges at step 2.

2. `img-edge` negotiates `webp` for Jonas Ek in Chrome 129. It caches under `/img/tr-1180.jpg?w=800` plus `webp`.
3. Hanna Lind opens the same page in Safari 13 at 08:05.
4. `img-edge` negotiates `orig` for her. It finds no entry under the `orig` key, renders the original and caches it.
5. Safari 13 decodes the original. Hanna sees the image.

**What changes**

- `edge/cache.py` old behaviour: `cache_key(request)` returns path and query string. New behaviour: it also takes the negotiated format and appends it. `lookup` and `save` pass the format through.
- `edge/handler.py` old behaviour: calls `negotiate` and uses the result only to render. New behaviour: passes the same result to `lookup` and `save`.
