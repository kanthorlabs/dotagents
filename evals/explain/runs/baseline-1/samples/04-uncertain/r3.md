`report-builder` returned an empty report for `northwind` because `hide_archived` was on for that tenant and `0042_archive_paid_invoices.sql` had archived all 188 of its October invoices. The flag was on for `northwind` only. `acme` and `globex` kept their archived invoices in the report.

**Timeline without the fix**

1. Migration 0042 runs on 2026-10-25 22:10 UTC. `migrations/0042_archive_paid_invoices.sql:2-4` sets `status = 'archived'` for every paid invoice. `migrations/README.md` promises only invoices older than 90 days, but the SQL has no date filter.
2. All 188 October invoices of `northwind` are now `archived`. Priya Raman's count in `logs/invoice-counts-2026-10-26.txt` shows 188 archived and 0 paid.
3. `report-builder` starts at 02:00:01 UTC on 26 October. `flagd` is unreachable, so `ledgerly.flags` serves cached flags that are 3 days old.
4. `build_monthly_report` calls `flags.is_on("hide_archived", tenant=tenant)`. It adds `AND status <> 'archived'` when the flag is on (`jobs/report_builder.py:10-11`).
5. The counts show which tenants had the flag on:
   - `acme` reports 412 invoices, but 301 of them are archived. The filter was off.
   - `globex` reports 97 invoices, but 64 of them are archived. The filter was off.
   - `northwind` reports 0 invoices, and all 188 are archived. The filter was on.
6. `render` returns `{"count": 0, "lines": []}`. The job logs `report=ok`, because an empty result is not an error. The October report for `northwind` is empty.

**Unverified step.** Step 5 is an inference from the counts. Only a filter that was on for `northwind` and off for the other two tenants explains 0 against 412 and 97. No file records the flag value itself. The `flagd` audit log or the cached flag file on the job host would settle it. Those would also show whether the live flag differed from the 3-day-old cache. I skipped the fix timeline until that evidence arrives.

**Two defects, not one**

- **Migration.** It ignores its own 90-day rule and archives recent paid invoices.
- **Report.** It treats archived as "hide", so any tenant with the flag on loses every archived invoice from a monthly report. It also reports `ok` with a zero count and no warning.

**Recommendation.** Aelita recommends fixing the migration side first. It is the root cause, because the flag would hide nothing important if only old invoices were archived. The repair has to restore invoices archived by mistake, and the data cannot say which `archived` rows were archived before 0042. The restore needs a backup or a pre-migration snapshot, or the migration's `updated_at` values. A restore without that evidence can un-archive invoices that were archived on purpose.

**Alternative: change only `report-builder`.** Stop filtering archived invoices in monthly reports, or log a warning when the count is 0 but the tenant has invoices in the period. This is a one-line change with no data risk. It leaves the wrongly archived data in place. It becomes the primary if no snapshot exists to restore from.
