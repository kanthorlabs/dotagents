Migration 0042 archived every paid invoice instead of only those older than 90 days. `report-builder` then filtered out the archived rows for `northwind`, so all 188 October invoices disappeared. Aelita recommends restoring the wrongly archived rows and rerunning the report.

**Timeline without the fix**

1. `migrations/0042_archive_paid_invoices.sql` runs on 25 Oct at 22:10 UTC. Its `WHERE status = 'paid'` has no age condition, although `migrations/README.md` says "older than 90 days".
2. Every paid invoice becomes `archived`. Priya Raman's counts show 0 paid invoices left for all three tenants.
3. `report-builder` starts on 26 Oct at 02:00 UTC. `flagd` is unreachable, so it uses cached flags that are 3 days old.
4. `build_monthly_report` reads `hide_archived` per tenant. For `northwind` the cached value is on, so the SQL adds `AND status <> 'archived'` (`jobs/report_builder.py:10-11`).
5. All 188 October invoices of `northwind` are `archived`, so the query returns 0 rows.
6. The job logs `tenant=northwind invoices=0 report=ok`. The empty report counts as a success, so nothing alerts anyone.

**Evidence for step 4.** `acme` and `globex` still reported 412 and 97 invoices, although 301 and 64 of theirs are archived. Those two tenants must have had the flag off. Only `northwind` had it on. The cache hides who set the flag and when, and the missing `flagd` audit log would show that. It does not change the cause, because the cached value is what the job used.

**Timeline with the fix**, diverges at step 2.

2. The migration is corrected to archive only paid invoices older than 90 days. Invoices from October stay `paid`.
3. `report-builder` runs with the same cached flags.
4. `hide_archived` is on for `northwind`, but the October invoices are `paid`, not `archived`.
5. The query returns 188 rows.
6. The log reads `tenant=northwind invoices=188`.

**What changes**

- `migrations/0042_archive_paid_invoices.sql`: add `AND issued_at < <migration time> - INTERVAL '90 days'` to the `WHERE`.
- `invoices` table: a one-off restore sets `status = 'paid'` for archived rows issued inside the 90-day window. Run it after you check it against a backup or the replica.
- `jobs/report_builder.py`: no change is needed. The filter works as designed.

**Recommendation.** Aelita recommends fixing the migration and restoring the data, because the bad migration is the root cause.
