The handler credits and debits the ledger before it checks the signature, so anyone who can reach the endpoint can move money. I could only review `pr-311.diff`, because the directory holds no other files. Aelita recommends blocking the merge until B1 to B4 are fixed.

**Blockers**

- **B1** - status:OPEN - action:YES - Signature checked after the ledger write - `handle` calls `ledger.credit` and `ledger.debit` at lines 22 to 25. It calls `verify` at line 27. A forged request changes the ledger and then gets a 400. - fix: call `verify` first and return 400 before `json.loads` and any ledger call. - why: an unauthenticated caller can credit any `account_id` with any `amount_cents`.
- **B2** - status:OPEN - action:YES - Default webhook secret - `settings.py` sets `WEBHOOK_SECRET = os.environ.get("QUILL_WEBHOOK_SECRET", "dev-secret")`. If the variable is missing in production, the secret is public. - fix: use `os.environ["QUILL_WEBHOOK_SECRET"]`, like `DATABASE_URL` on the line above. - why: a missing variable should stop startup, not make forged signatures valid.
- **B3** - status:OPEN - action:YES - No replay or duplicate protection - `verify` accepts any valid request for 300 seconds, and `handle` never records the event id. A replayed or retried `charge.succeeded` credits the account twice. - fix: store the event id with a unique constraint and skip events that are already processed. Apply the ledger write in the same transaction. - why: payment providers retry deliveries, and a double credit is a direct money error.
- **B4** - status:OPEN - action:YES - Non-constant-time comparison - `verify` ends with `expected == parts.get("v1")`. - fix: use `hmac.compare_digest(expected, parts.get("v1", ""))`. - why: a plain `==` leaks timing information about the expected signature.

**Suggestions**

- **S1** - status:OPEN - action:YES - Malformed header crashes `verify` - `dict(item.split("=", 1) ...)` raises `ValueError` on an item without `=`. `int(...)` raises on a non-numeric `t`. Both give a 500. - fix: wrap the parsing in `try/except (ValueError)` and return `False`. - why: a bad header should give a 400, not a server error.
- **S2** - status:OPEN - action:YES - Full payload in the log - line 20 logs `payload` before any check. It holds account ids and amounts, and it holds unverified input. - fix: log only `event["id"]` and `event["type"]` after verification. - why: this limits financial data in logs and log injection.
- **S3** - status:OPEN - action:YES - Missing keys and unknown types - `event["data"]["account_id"]` raises `KeyError` on a bad body. An unknown `type` returns 200 with no trace. - fix: validate the fields, return 400 on a bad body, and log unknown types at info level. - why: this makes failures visible and avoids provider retry storms.
- **S4** - status:OPEN - action:NO - Currency is ignored - `LEDGER_CURRENCY` is `"EUR"`, but the handler never checks the event currency. - fix: reject an event whose currency differs from `LEDGER_CURRENCY`. - why: a non-EUR amount would be booked as EUR.
- **S5** - status:OPEN - action:YES - Dead code and no tests - `_unused_helper` does nothing. The diff has no test for `verify` or `handle`. - fix: delete the helper. Add tests for a bad signature, an old timestamp, a replay and a valid event. - why: B1 and B3 are exactly the cases a test would have caught.
