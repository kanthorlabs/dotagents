The handler in `quillpay/webhooks.py` changes the ledger before it checks the signature, so any unsigned request can credit or debit an account. Aelita recommends that `handle` verifies first and rejects before it parses or acts. The fix costs a reorder of about five lines.

**Timeline without the fix**

1. An attacker posts a `charge.succeeded` body to `handle` with `account_id` set to their own account. The request has no `Quill-Signature` header.
2. `handle` runs `json.loads` on the body and logs the full payload at line 20.
3. `handle` matches `charge.succeeded` and calls `ledger.credit` at line 23.
4. `handle` calls `verify` at line 27. The header is empty, so `header.split(",")` yields `""`, and `item.split("=", 1)` gives one element. `dict` raises `ValueError`.
5. The request ends in a 500 or 400. The credit from step 3 is already written. The attacker holds free balance.

**Timeline with the fix**, diverges at step 2.

2. `handle` calls `verify` on the raw body first. A missing or bad header returns 400.
3. `handle` never reaches `json.loads` or `ledger.credit`. The ledger stays unchanged.

**Findings**

- **B1** - status:OPEN - action:YES - Ledger mutated before signature check - `ledger.credit` and `ledger.debit` at lines 22-25 run before `verify` at line 27. A 400 reply does not undo the write. - fix:move the `verify` call to the top of `handle` and return 400 before `json.loads` - why:the signature is the only proof that Quill sent the event.
- **B2** - status:OPEN - action:YES - Default secret `dev-secret` - `quillpay/settings.py` line 52 falls back to `"dev-secret"` when `QUILL_WEBHOOK_SECRET` is unset. A misconfigured production host then accepts signatures that anyone can compute. - fix:use `os.environ["QUILL_WEBHOOK_SECRET"]`, as `DATABASE_URL` does on the line above - why:it fails at startup instead of failing open.
- **B3** - status:OPEN - action:YES - No replay or duplicate protection - The diff does not read an event id. A provider retry, or a replay inside the 300 second window, credits the account twice. - fix:store the event id with a unique constraint and skip events already seen, in the same transaction as the ledger write - why:payment providers retry deliveries, so duplicates will arrive. I read only this diff, so I could not check whether `ledger.credit` already dedupes.
- **S1** - status:OPEN - action:YES - Malformed header crashes `verify` - A part without `=` or a non-numeric `t` raises `ValueError` at lines 33-34. - fix:wrap the parse in `try/except ValueError` and return False - why:bad input should give 400, not a 500.
- **S2** - status:OPEN - action:YES - Non-constant-time compare - Line 42 uses `==` on the signature. - fix:use `hmac.compare_digest(expected, parts.get("v1", ""))` - why:it removes a timing side channel.
- **S3** - status:OPEN - action:YES - Full payload logged - Line 20 logs the raw body, and it does so before verification. - fix:log only the event id and type, after verification - why:it keeps account data out of the logs and stops unsigned traffic from filling them.
- **S4** - status:OPEN - action:YES - Unhandled event shape - `event["data"]["account_id"]` raises `KeyError` on a missing field. - fix:validate the fields after verification and return 400 on a bad shape - why:the provider should get a clear reply instead of a 500.
- **S5** - status:OPEN - action:YES - Dead code and missing tests - `_unused_helper` at line 45 does nothing, and the diff adds no tests. - fix:delete the helper and add tests for a bad signature, an old timestamp, a replay, and each event type - why:B1 and B3 are the kind of bug that tests catch.

**Recommendation.** Aelita recommends fixing B1 first, with the verify-then-parse order, because it is the exploitable path and the smallest change. The cost is that `verify` must read the raw body, which `request.body` already provides. An unsigned test client in the existing tests will break.

**Alternative: reject unsigned requests in middleware.** A middleware checks the signature for every webhook route. It beats the handler fix when more webhook handlers are coming. It costs a new layer and a route list. It becomes the primary when a second handler joins `quillpay`.
