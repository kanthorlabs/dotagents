`export_contacts` in `app/exports.py` builds the whole CSV in memory before it sends a byte, so `edge-lb` closes the idle connection at 30 seconds. Aelita recommends streaming the CSV row by row so bytes flow from the first second.

**Existing behaviour**

1. `export_contacts` runs one `SELECT` for the tenant and loads every row.
2. It writes all rows into an `io.StringIO` buffer.
3. It returns `Response(buffer.getvalue())` only after the buffer is complete.
4. `edge-lb` sets `idle_timeout_seconds: 30` and `request_timeout_seconds: none`. The idle timer restarts on every upstream byte.

**Timeline without the fix**

1. A user at `bluefin-logistics` clicks "Export contacts". `edge-lb` forwards the request to `ferngrove-web`.
2. The query takes 12 seconds for 412880 rows. No byte goes out.
3. The CSV build takes 77 seconds. No byte goes out.
4. `edge-lb` sees 30 seconds of silence and closes the connection.
5. The user gets a 504. The log shows `status=504 reason=edge-lb-idle-timeout` at 09:12 and again at 14:02.

`harrow-dental` has 3120 rows and finishes in 1 second, which is why only the largest tenants fail.

**Timeline with the fix**, diverges at step 2.

2. The query streams rows through a server-side cursor. `export_contacts` yields the header line at once.
3. The generator yields CSV chunks as rows arrive. The idle timer restarts on each chunk.
4. The export finishes after about 90 seconds with no silent gap.
5. The user receives the full file with a 200.

**What changes**

- `app/exports.py`: old behaviour is a `StringIO` buffer returned in one piece. New behaviour is a generator that yields the header and then rows in batches, passed to `Response` as an iterable.
- `deploy/gunicorn.conf.py`: no change now. `timeout = 120` stays.

**Recommendation.** Aelita recommends streaming. It removes the root cause, which is that no byte is sent while the work runs. It needs no new component and no config change. Two things can break it:

- **Response support:** I could not confirm that `ferngrove.web.Response` accepts an iterator. The `ferngrove` package is not in this repository.
- **Worker timeout:** with sync gunicorn workers, `timeout = 120` can still kill a very large export, because the whole request is limited to 120 seconds. `bluefin-logistics` takes about 90 seconds today, so it has little headroom.

**Alternative: raise `idle_timeout_seconds` in `deploy/edge-lb.yaml`.** This is a one-line change. It beats streaming on effort. It only moves the limit, and every tenant larger than `bluefin-logistics` fails again. It becomes the primary if `Response` cannot stream and a fix is needed today.

**Alternative: background job that emails a download link.** It has no size limit. It needs a job queue and an email service. `docs/exports.md` says neither exists and each new one needs an owner and on-call coverage. It becomes the primary if exports grow past the 120 second worker limit.
