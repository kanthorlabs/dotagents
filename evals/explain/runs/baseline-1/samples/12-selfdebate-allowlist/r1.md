`plugin_env` in `runner/spawn.py` hands each plugin the whole runner environment minus a fixed list, so `STRIPE_API_KEY` leaked as soon as it was added to the runner. Aelita recommends an allowlist instead of your two-name denylist addition. It stops this class of leak, not just these two names.

**Timeline without the fix**

1. On 2 October the runner environment gains `STRIPE_API_KEY` for the billing worker. `SENTRY_DSN` is already there.
2. `run_plugin` calls `plugin_env("feed-fetch")`. It copies all of `os.environ` and pops only `AWS_SECRET_ACCESS_KEY`, `DATABASE_URL` and `GITHUB_TOKEN`.
3. `STRIPE_API_KEY` is not in `DENYLIST`, so it reaches the `feed-fetch` process.
4. On 24 October a customer sends a `feed-fetch` request with `debug` set. `plugins/feed-fetch/main.py:13-14` prints `dict(os.environ)` to stderr.
5. The customer pastes that stderr into a public support ticket. The ticket shows `STRIPE_API_KEY` and `SENTRY_DSN`. Selin Aydin rotates the key the same day.

**Timeline with the fix**, diverges at step 2.

2. `plugin_env("feed-fetch")` builds the environment from an allowlist. It keeps only `PATH`, `HOME`, `HTTPS_PROXY` and names that start with `TINKERBOX_`.
3. `STRIPE_API_KEY` and `SENTRY_DSN` are not on the list, so neither reaches `feed-fetch`.
4. The `debug` request still prints the environment to stderr.
5. The ticket shows only allowlisted values. No secret is exposed.

**What changes**

- `runner/spawn.py`: delete `DENYLIST` and the pop loop in `plugin_env`. Add `ALLOW_EXACT = {"PATH", "HOME", "HTTPS_PROXY"}` and `ALLOW_PREFIX = "TINKERBOX_"`. `plugin_env` copies only matching names, then sets `TINKERBOX_PLUGIN_DIR` as before.
- `plugins/feed-fetch/main.py`: no change required. Its `debug` dump becomes harmless. The dump itself is still poor practice.

**Recommendation.** Aelita recommends the allowlist, because the denylist fails open. Every new runner secret leaks until someone remembers to list it. That is how `STRIPE_API_KEY` leaked, and your edit would repeat the pattern for the next secret. The allowlist matches `docs/plugin-contract.md`, which says plugins read settings from `TINKERBOX_*`. I found plugins reading three other names:

- `HOME` in `pdf-stamp`.
- `HTTPS_PROXY` in `feed-fetch`.
- `PATH`, which I added for subprocess lookups. No plugin I found needs it.

The cost is that a plugin needing another variable fails until it is added. That failure is visible, where a leak is silent.

**Alternative: extend the denylist as you planned.** Add `STRIPE_API_KEY` and `SENTRY_DSN` to `DENYLIST`. It is a two-name change and no plugin can break. It becomes the primary only if an unknown plugin outside this repository needs the full environment and cannot be audited this week. It leaves every future secret exposed.
