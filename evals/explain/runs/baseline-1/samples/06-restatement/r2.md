- **Schedule runs every 10 minutes: correct.** `config/prod.yaml:2` sets `session_gc_schedule: "*/10 * * * *"`.
- **It deletes sessions idle for 30 minutes: correct.** `auth/session_gc.py:3` sets `IDLE_LIMIT` to 30 minutes. Line 8 deletes rows where `last_seen_at < cutoff`.
- **Local time against UTC: wrong.** `auth/session_gc.py:7` builds the cutoff with `datetime.now(timezone.utc)`, so it is timezone-aware. `auth/schema.sql:4` types `last_seen_at` as `timestamptz`, so Postgres compares two absolute instants. No local-time value enters the comparison. The case is not a timezone bug.

**The real cause stands.** `edge-proxy/session.py:8` calls `auth_client.touch` only when `touch_on_request` is true. `config/prod.yaml:1` sets it to false. Nothing updates `last_seen_at` after login, so `session-gc` is correct to delete the session 30 minutes later. It sees an idle session because no code records the activity.
