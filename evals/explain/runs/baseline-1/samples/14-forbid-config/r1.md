`purge-worker` deleted the in-progress uploads because `TenantConfig.validate` accepts `retention_days: 0`, while `docs/retention.md` supports only 1 to 3650. Aelita recommends making the validator enforce the documented range.

**Timeline without the fix**

1. The `acme-labs` tenant sets `retention_days: 0` in `tenants/acme-labs.yaml`.
2. `TenantConfig.validate` in `config/schema.py` checks only `< 0`. It accepts 0.
3. A user starts a multipart upload at 10:00. `created_at` is 10:00. The upload can stay in progress for up to 6 hours.
4. `purge-worker` runs at 10:15. `purge_tenant` computes `cutoff = now - timedelta(days=0)`, which is 10:15.
5. `upload.created_at < cutoff` is true for the 10:00 upload.
6. `store.delete` removes the upload while it is still in progress. The user loses it.

**Timeline with the fix**, diverges at step 2.

2. `TenantConfig.validate` rejects 0 with a `ValueError`. The tenant file is not accepted.
3. The tenant sets `retention_days: 1`. A multipart upload starts at 10:00.
4. `purge-worker` runs at 10:15. The cutoff is 24 hours back, so the 10:00 upload is not older than it.
5. The upload finishes within its 6 hours. The upload stays under the cutoff until the next day.
6. A tenant that wants no retention deletes uploads through the API, as the docs say.

**What changes**

- `config/schema.py` old behaviour: `if self.retention_days < 0` raises "retention_days must be >= 0". New behaviour: `if not 1 <= self.retention_days <= 3650` raises "retention_days must be between 1 and 3650".
- `tenants/acme-labs.yaml` old value: `retention_days: 0`. New value: `retention_days: 1`, so the file passes validation.

**Recommendation.** Aelita recommends the validator fix. It removes the root cause: config and docs disagree, and 0 was never a supported value. It costs one line. Any other tenant file with 0 will now fail validation. I searched the repository and found only `acme-labs` with that value. Any minimum of 1 day also covers the 6-hour upload limit.

**Alternative: skip in-progress uploads in `purge_tenant`.** The worker would skip any upload that is not complete. It protects uploads even when the retention is short. It needs a status field on the upload object. The repository holds no `store` code, so I cannot confirm that field exists. It becomes the primary if you decide that 0 must be a valid value.
