`validate` accepts `retention_days: 0`, but `docs/retention.md` supports only 1 to 3650. With 0, `purge-worker` sets its cutoff to now and deletes every upload that has started, including in-progress ones. Aelita recommends tightening `validate` to the documented range.

**Timeline without the fix**

1. `acme-labs` sets `retention_days: 0` in `tenants/acme-labs.yaml`.
2. `TenantConfig.validate` in `config/schema.py` checks only `< 0`. It accepts 0.
3. A user of `acme-labs` starts a multipart upload. It may stay in progress for up to 6 hours.
4. `purge-worker` runs its 15-minute cycle. `purge_tenant` computes `cutoff = now - 0 days`.
5. The in-progress upload has `created_at` before `now`, so `created_at < cutoff` is true.
6. `store.delete` removes the upload mid-transfer. `acme-labs` loses data that was still arriving.

**Timeline with the fix**, diverges at step 2.

2. `TenantConfig.validate` rejects 0 with an error. The tenant config does not load.
3. `acme-labs` must pick a value from 1 to 3650, or delete uploads through the API as the docs say. No purge runs with a zero cutoff.

**What changes**

- `config/schema.py` old behaviour: `validate` raises only when `retention_days < 0`. New behaviour: it raises unless `1 <= retention_days <= 3650`. The message becomes `retention_days must be between 1 and 3650`.
- `tenants/acme-labs.yaml` old value: `retention_days: 0`. New value: `1`, or the value that `acme-labs` chooses.

**Recommendation.** Aelita recommends enforcing the documented range in `validate`. It removes the cause: a value the docs never supported. It forbids the edge case instead of adding a mechanism. The cost is that `acme-labs` fails validation until it picks a new value. Any other tenant file with 0 breaks the same way. A search of this directory found only `tenants/acme-labs.yaml`, but I can't see tenants stored elsewhere.

**Alternative: skip in-progress uploads in `purge_tenant`.** `purge_tenant` skips any upload still in progress, so 0 would mean "delete once finished". It beats the recommendation when `acme-labs` needs 0 to mean immediate cleanup. It costs a state field on uploads. I found no such field in `store`, and the store code is not in this directory. It also contradicts the documented range.

**Question.** Do you approve enforcing 1 to 3650 in `validate` and changing `tenants/acme-labs.yaml` to a valid value, or do you want `purge_tenant` to skip in-progress uploads?
