Aelita recommends against dropping `legacy_sku` now. Your grep covered only `src/`, and `v_partner_feed` still reads the column to feed Oakline Supply. Dropping it would silently change the partner keys of 6,140 products.

**Existing behaviour**

1. `db/schema.sql` defines `products.legacy_sku` as nullable text.
2. `importers/brightstock_import.py` filled it once with the Brightstock item code on 12 March 2024.
3. `db/views.sql` defines `v_partner_feed` with `COALESCE(p.legacy_sku, p.sku) AS partner_ref`.
4. `jobs/partner_feed_export.py` reads `partner_ref` from the view every night. It uploads the CSV to `sftp.oaklinesupply.com`.

**Timeline without the fix**

1. You run `ALTER TABLE products DROP COLUMN legacy_sku`.
2. Postgres refuses, because `v_partner_feed` depends on the column.
3. Someone adds `CASCADE` to get past the error. Postgres drops `v_partner_feed` too.
4. `partner_feed_export` runs that night. Its query fails on the missing view, and no feed reaches Oakline Supply.
5. Suppose instead someone rewrites the view as `SELECT p.sku AS partner_ref`. The job succeeds.
6. The feed now carries new SKUs for the 6,140 migrated products. Oakline Supply still keys on Brightstock codes, so it cannot match them. The failure is silent.

**What changes**

- `db/schema.sql` stays unchanged for now.
- `db/views.sql` stays unchanged for now.
- No file changes until Oakline Supply stops keying on Brightstock codes.

**Recommendation.** Aelita recommends keeping `legacy_sku`. The column is live partner data, and `src/` is the wrong place to check for it. The cost is one unused-looking column on `products`. Nothing breaks. Drop it only after Oakline Supply re-keys its catalog to the new `sku`. At that point, change the view first and drop the column second.

**Alternative: move the codes to a `partner_refs` table.** Copy `legacy_sku` into `partner_refs(product_id, partner, ref)`. Repoint `v_partner_feed` at it, then drop the column. This cleans `products` without waiting for Oakline Supply. It costs a migration, a backfill of 6,140 rows, and a check that the feed output is identical. It becomes the primary if you need the column gone before Oakline Supply re-keys.
