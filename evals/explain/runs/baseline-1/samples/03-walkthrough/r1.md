`mintctl deploy staging` builds the current checkout of `mint-shop`, pushes it to `registry.mint.internal`, rolls it out to `gke-mint-staging`, then posts to Slack. No CLI entry point exists in this directory, so I assume it calls `deploy("staging")` in `mintctl/deploy.py:7`.

**Timeline**

1. **Config.** `deploy` opens `mint.toml` from the working directory, so Ines Albrecht must run it at the `mint-shop` repo root. It reads `env.staging`: cluster `gke-mint-staging`, namespace `shop`, channel `#deploys-staging`.
2. **Version.** `git rev-parse --short HEAD` returns the short commit hash, `sha`. The image tag becomes `registry.mint.internal/mint-shop:<sha>`.
3. **Build.** `docker build -t <tag> .` builds from the repo root. `check=True` aborts the command on any failure.
4. **Push.** `docker push <tag>` uploads the image to `registry.mint.internal`.
5. **Release.** `kubectl --context gke-mint-staging -n shop set image deployment/mint-shop web=<tag>` points the `web` container at the new image.
6. **Wait.** `kubectl rollout status deployment/mint-shop --timeout=300s` blocks until the rollout finishes. It fails after 300 seconds.
7. **Notify.** `slack.post` sends `mint-shop <sha> is live on staging` to `#deploys-staging`. It uses the webhook in `MINT_SLACK_WEBHOOK` with a 10-second timeout.

**Behaviours to know**

- **Dirty tree.** The tag uses `HEAD`, so uncommitted changes are built into the image under a hash that does not describe them.
- **No rollback.** A failed or timed-out rollout in step 6 stops the command with no Slack message and no undo.
- **Late Slack failure.** If `MINT_SLACK_WEBHOOK` is unset, step 7 raises `KeyError` after the deploy has already succeeded.
