`export_invoices` in `app/exports.py` builds the whole CSV in memory before it sends a byte, so `gw-billing` cuts the connection after 30 idle seconds. Aelita recommends moving the export to the `documents` queue of `taskq` and emailing a signed link, as `render_invoice_pdf` already does.

**Timeline without the fix**

1. An accountant at `northfield-accounting` calls `GET /exports/invoices.csv`. A `tallyhall-web` gunicorn worker takes the request.
2. `db.query` loads all 1,840,211 rows in 18 seconds. The handler sends no byte.
3. `csv.writer` fills a `StringIO` for 222 seconds. The response only starts after `buffer.getvalue()`.
4. `gw-billing` sees 30 seconds with no byte, because `idle_timeout_seconds` is 30. It closes the connection and returns 504.
5. The worker keeps building for the full 240 seconds. The log shows `total_seconds=240`, which is under the 300-second `request_timeout_seconds` and `timeout`. So the idle timeout is the cause, not the total timeout.
6. About 900 exports run in two days at month end. The log shows `web_workers_busy=12/12` and `/invoices` p99 at 9.4 seconds, against 0.4 seconds on 2026-10-15.
7. The accountant retries and starts another long build. Large tenants never get a file, and the other routes slow down.

**Timeline with the fix**, diverges at step 2.

2. `export_invoices` enqueues `render_invoice_csv` on queue `documents` and returns 202 in milliseconds. The worker is free.
3. A `taskq` worker runs the query and writes rows to a CSV file. No gateway timer applies there.
4. The task calls `storage.put` for `exports/<id>.csv`, then `storage.signed_url`.
5. The task calls `mailer.send` with the link to the accountant.
6. At month end, the 900 exports queue on `documents`. `tallyhall-web` workers stay free for `/invoices`.
7. The accountant downloads the file from storage. Large tenants succeed.

**What changes**

- `app/exports.py`: `export_invoices` old behaviour builds and returns the CSV inline. New behaviour enqueues a task and returns 202.
- `jobs/invoice_csv.py`: add `render_invoice_csv(tenant_id, recipient)`, modelled on `render_invoice_pdf`. It writes rows to a file instead of a `StringIO`, then calls `storage.put`, `storage.signed_url` and `mailer.send`.
- `docs/exports.md`: add one line that exports are emailed, not returned inline.

**Recommendation.** Aelita recommends the queued export. It removes the cause, which is a long synchronous request behind a gateway with a timer. It also frees the workers at month end. It costs a changed contract: callers get a 202 and an email, not a file. Two things can break it. Any client that parses the CSV from the response body will fail. `documents` also shares capacity with invoice PDFs during the month-end peak.

**Alternative: stream the CSV from the handler.** `export_invoices` returns a generator that yields rows from a server-side cursor. The first byte arrives in seconds, so the idle timeout stops firing. The contract stays the same. It still holds a worker for minutes per export, so the 12/12 saturation stays. A tenant that needs more than 300 seconds still gets cut. It becomes the primary if clients must get the file in the response.
