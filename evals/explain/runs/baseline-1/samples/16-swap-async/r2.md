`export_invoices` sends no byte until it has built the whole CSV, so `gw-billing` closes the connection after 30 idle seconds. Aelita recommends moving the export to the `documents` queue of `taskq` and emailing a signed link, as `render_invoice_pdf` already does.

**Timeline without the fix**

1. An accountant at `northfield-accounting` requests `/exports/invoices.csv`. The tenant has 1,840,211 invoices.
2. `export_invoices` runs `db.query`, which takes 18 seconds. It then builds the CSV in a `StringIO` for 222 seconds. It sends nothing in that time.
3. `gw-billing` reaches `idle_timeout_seconds: 30` and returns 504 to the accountant.
4. The gunicorn worker does not know the client left. It keeps building until second 240.
5. At month end about 900 exports run in two days. The log shows `web_workers_busy=12/12` and `/invoices` p99 at 9.4 seconds, against 0.4 seconds on 2026-10-15.
6. The largest tenants never receive a file. Their exports also starve the `/invoices` route of workers.

**Timeline with the fix**, diverges at step 2.

2. `export_invoices` enqueues `render_invoice_csv(tenant_id, recipient)` on queue `documents`. It returns 202 in milliseconds.
3. A `taskq` worker runs the query and writes rows to `storage` in chunks. No gateway timeout applies.
4. The task calls `storage.signed_url` and `mailer.send`. The accountant gets a download link.
5. The 12 gunicorn workers stay free, so `/invoices` latency stays flat at month end.

**What changes**

- `app/exports.py`: `export_invoices` currently queries and builds the CSV inline. It will validate the request, enqueue the task and return 202.
- `jobs/invoice_csv.py`: add `render_invoice_csv`, modelled on `jobs/invoice_pdf.py`. It streams rows into `storage.put` and sends the link with `mailer.send`.

**Recommendation.** Aelita recommends the queued export. It removes the root cause, which is long work inside a request, and it reuses `taskq`, `storage` and `mailer`. It costs a change in behaviour: the accountant gets an email instead of an instant download. It can also load the `documents` queue at month end. Queue capacity is the one thing to watch.

**Alternative: stream the response.** `export_invoices` yields rows as it reads them, so the idle timeout never fires. It keeps the instant download and needs no new job. It still holds a gunicorn worker per export. It also hits `request_timeout_seconds: 300`, and northfield already needs 240 seconds. It becomes the primary if accountants must download in the browser and no tenant exceeds about 250 seconds.
