The stale price comes from the per-pod `price_cache` in `shop-api`, not from the CDN. Lowering the CDN TTL would change nothing. Aelita recommends that every `shop-api` pod subscribe to `price.changed` and drop its own cached SKU.

**Timeline without the fix**

1. Tove Lindqvist changes KET-2210 from 39.90 to 34.90 in the admin at 10:02. The load balancer sends the POST to one of the 6 `shop-api` pods, for example pod A.
2. `update_price` in `admin/prices.py` writes the database. It runs `price_cache.pop(sku)` in pod A only, because `price_cache` is a per-process `TTLCache`.
3. `update_price` publishes `price.changed`. Only `search/indexer.py` subscribes. No `shop-api` pod listens.
4. Pods B to F still hold 39.90 for KET-2210 in `price_cache`, with `ttl=3600`.
5. A product page calls `/api/prices?sku=KET-2210`. The CDN rule for `/api/*` has `cache: false`, so the request reaches a random pod. Pod A returns 34.90. Pods B to F return 39.90. This is the mix Tove saw on reload.
6. Each stale pod expires its entry up to 3600 seconds after it cached it. The last old price appeared at 10:57. Customers see 39.90 at checkout for up to an hour.

**Timeline with the fix**, diverges at step 3.

3. `update_price` publishes `price.changed`. Each `shop-api` pod runs a handler that calls `price_cache.pop(sku, None)`.
4. Pods B to F drop KET-2210 within about 0.5 seconds. That is the `sleep_time` in `shared/events.py`.
5. The next `/api/prices` call on any pod misses the cache and reads 34.90 from the database.
6. Every customer sees 34.90 within about a second.

**What changes**

- `pricing/service.py` add `start_invalidation()`. It calls `subscribe("price.changed", lambda e: price_cache.pop(e["sku"], None))`.
- `shop/app.py` add a startup call to `start_invalidation()`. I did not find this file in the repository. The deployment runs `shop.app:app`, so the call belongs there.
- `admin/prices.py` keep the local `pop`. It is harmless and makes pod A instant.
- `cdn/rules.yaml` no change. The proposed TTL edit would touch `/product/*`, which holds no price (`docs/frontend.md`), or have no target at all.

**Recommendation.** Aelita recommends the pub/sub invalidation. It reuses the `price.changed` event that already exists and removes the cause, which is that 6 caches have no shared signal. It costs one Redis subscription per pod. A pod that misses a message while Redis is down keeps the old price until its TTL runs out.

**Alternative: lower `ttl` on `price_cache` from 3600 to 60.** This is one line and needs no Redis. It caps the stale window at 60 seconds, but customers still see mixed prices for up to a minute. It becomes the primary if the team will not add a subscriber to the API pods.

**Alternative: remove `price_cache` and read the database each time.** This gives exact prices with no invalidation logic. It costs a database read per price call. It becomes the primary if the price table is small and the read load is low.
