- **Today's key is the URL only: correct.** `cache_key` in `edge/cache.py:5` returns `request.path` plus `request.query_string`.
- **The fix appends the whole `Accept` header: wrong.** The ruling appends the negotiated format: `avif`, `webp` or `orig`.
- **Safari 13 cannot decode WebP: correct.** `docs/browser-support.md` adds that Safari 13 cannot decode AVIF either.

The case is not a key built from the raw header. The key gets one of three short values.

**Why not the whole header.** `logs/accept-stats-2026-10.txt` counts 1,912 distinct `Accept` values in October. Each value would get its own cache entry for the same image. The three formats are 58 %, 31 % and 11 % of requests.

**Timeline with the fix**, diverges at step 4.

4. `img-edge` negotiates `orig` for Hanna Lind's Safari 13 header. It builds the key `/img/tr-1180.jpg?w=800` plus `orig`. Jonas Ek's entry sits under the `webp` key, so this is a miss. `img-edge` renders the original.
5. Safari 13 receives the original JPEG. Hanna sees the image.

**What changes**

- `edge/cache.py` old behaviour: `cache_key(request)` returns path and query string. New behaviour: `cache_key(request, image_format)` appends the format. `lookup` and `save` take `image_format` and pass it on.
- `edge/handler.py` old behaviour: `serve_image` calls `lookup` at line 7, before `negotiate` at line 10. New behaviour: `serve_image` calls `negotiate` first, then `lookup` with the format. Without this move the key cannot hold the format.

**Side effect.** Old entries use keys without a format. They never match again and expire after the 86400 second TTL.
